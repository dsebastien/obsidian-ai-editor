> Reviewer: `codex exec -m gpt-5.6-sol -c model_reasoning_effort=xhigh --sandbox read-only` against `documentation/plans/ai-editor-v1-implementation-plan.md` @ f69e9e2. Verbatim output below.

Verdict: do not begin M1 from this plan. It is a strong product vision, but the proposed core contracts cannot safely implement several promised surfaces, and M0 does not de-risk the hardest integration points.

1. **Blocker — The backend/finding contract cannot represent the product.** `review()` plus quote-based findings cannot model insertion-only continuation, “say more,” delete operations, refinement turns, research evidence, or panel scorecards. “Apply” also contradicts the rule that every change must pass through an Accept/Reject diff. Replace it with versioned, discriminated operations such as `Review`, `TransformSelection`, `InsertAt`, `RefineProposal`, `ThreadTurn`, and `AggregatePanel`, each with its own result schema and stable IDs. See [backend abstraction](/home/dsebastien/wks/obsidian-ai-editor/documentation/plans/ai-editor-v1-implementation-plan.md:152) and [finding contract](/home/dsebastien/wks/obsidian-ai-editor/documentation/plans/ai-editor-v1-implementation-plan.md:167).

2. **Blocker — Live Preview and Source mode will not render “identically.”** Both use a CM6 source document, but Live Preview replaces/hides Markdown syntax and uses its own widgets. Marks spanning links, embeds, headings, code, properties, math, callouts, or hidden syntax can disappear, split, or collide. Use `editorLivePreviewField`, not `MarkdownView.getMode()`, to select a mode-aware projection. Promise equivalent actions and semantics, not identical rendering. Prototype against a Markdown fixture corpus before general UI work. The relevant API exists in [obsidian.d.ts](/home/dsebastien/wks/obsidian-ai-editor/node_modules/obsidian/obsidian.d.ts:2419).

3. **Blocker — Asynchronous results have no snapshot or concurrency model.** The model quotes the request snapshot while the user keeps editing. Matching the response against the current document can select the wrong occurrence; matching the old snapshot produces obsolete offsets. Store a content hash/snapshot ID with every run, map ranges through every CM6 `ChangeDesc`, and mark a proposal stale when a change intersects its original range. Before Accept, verify the current slice still equals the proposal’s expected text. Never silently fuzzy-relocate an edit proposal.

4. **Blocker — “Decorations remap automatically” is false as specified.** A state field must explicitly map its `DecorationSet` through `transaction.changes`; that only moves the decoration, not the `Finding.anchor` later used for Apply. State effects also need mapping functions. Define one authoritative mapped anchor store, overlap detection using changed ranges, and transaction preconditions.

5. **Blocker — Exact-quote anchoring is internally incomplete.** The fallback says it uses prefix/suffix hints, but normal findings do not contain either. Repeated quotations are ambiguous, normalized matching needs a reversible source-offset map, and a fixed Levenshtein threshold can confidently select the wrong paragraph. Add block/chunk identifiers, occurrence/context hints, source snapshot hash, prefix/suffix, and match confidence. Only exact or uniquely contextualized matches should be actionable; fuzzy matches should be display-only until confirmed.

6. **Blocker — Streaming is assumed before a viable Obsidian transport exists.** `requestUrl` buffers the response and exposes no stream, while direct renderer `fetch` can encounter CORS/provider incompatibilities. Generic incremental parsing of one JSON object is also unsafe across SSE boundaries, escaped strings, split Unicode, and fragmented tool arguments. Make an M0 transport spike across every provider. Support buffered structured output as the baseline; add provider-specific SSE/JSONL decoders only where verified. Validate each completed record and the final envelope, impose byte/time limits, and never scrape partial JSON heuristically. See [requestUrl](/home/dsebastien/wks/obsidian-ai-editor/node_modules/obsidian/obsidian.d.ts:5185).

7. **Blocker — CLI execution is a security boundary, not another provider adapter.** `cwd = vault` does not sandbox anything. Agent CLIs may discover vault instructions, hooks, plugins, MCP servers, tools, environment secrets, and writable files. Headless Claude currently skips workspace trust; the local Codex executable is a network-resolving wrapper, showing that “found on PATH” does not mean stable or side-effect-free. Spawn without a shell, pass content over stdin, use an isolated working directory and allowlisted environment, disable tools/session persistence/customizations by default, enforce read-only sandbox flags, pin/test supported protocol versions, and kill the entire process tree on cancel/unload. Research/tool-enabled mode needs a separate, explicit warning and consent flow.

8. **Blocker — The manifest contradicts the desktop-only architecture.** It currently declares `"isDesktopOnly": false` while the plan requires child processes and `FileSystemAdapter`. Mobile users could install code that cannot run. Set desktop-only in M0, not M5, and test the minimum public Obsidian version. See [manifest.json](/home/dsebastien/wks/obsidian-ai-editor/manifest.json:7).

9. **Major — The provider taxonomy is inconsistent and too vague.** The plan defines `Backend` twice with different provider unions; one omits Azure and another invents separate OpenAI/OpenRouter cases. “OpenAI-compatible” is not a protocol guarantee: endpoint paths, schema support, usage events, streaming, auth, and error bodies differ. Define explicit adapter profiles and capability negotiation. Separate native OpenAI, a narrowly defined compatible Chat Completions profile, Anthropic, Ollama, Azure OpenAI, and Azure AI Model Inference if both Azure surfaces are intended.

10. **Major — Azure AI Foundry is radically under-specified.** Deployment-based Azure OpenAI and Foundry model endpoints have different URLs, credentials, model selection, and supported parameters. “Deployment + api-version + auth header” is not a first-class design. Choose the exact Azure surfaces supported in v1, authentication mechanisms, endpoint templates, validation rules, and structured-output fallback behavior.

11. **Major — The abstraction lacks essential lifecycle operations.** `ReviewBackend.review()` has no `AbortSignal`, health check, model discovery, capability report, usage, request ID, normalized errors, retry policy, or resumable-job semantics. Define an adapter contract covering these explicitly, including event ordering and a terminal event exactly once. Late events from cancelled runs must be discarded by run ID.

12. **Major — “Results survive Obsidian restarts” is not credible.** Persisted comment metadata can survive, but an HTTP stream or child process owned by Obsidian normally cannot. On startup, mark running jobs as interrupted and offer Retry. Only claim resumption for a backend that returns a durable remote job ID with a polling protocol.

13. **Major — Sidecar persistence lacks a storage design.** It needs a schema version, migrations, serialized writes, corruption recovery, file rename/delete handling, plugin unload recovery, sync-conflict policy, and compaction. Keying only by path breaks on rename. Put persistence behind a repository abstraction and define how settings saves and comment saves avoid races.

14. **Major — Context assembly is a privacy and token-budget hazard.** One-hop links plus prompt wikilinks can silently attach many sensitive notes. Define alias/heading/block/embed resolution, unresolved links, cycles, deduplication, path renames, source order, and a total token/byte budget—not merely a note count. Show a per-run “context being sent” preview and decide whether excluded notes can ever be included through an explicit wikilink.

15. **Major — Selection scope contradicts the request payload.** “Selection overrides” implies only the selection is sent, but §5.1 says every request includes the entire note plus an optional selection range. Resolve this explicitly. A privacy-preserving default is the selection plus bounded surrounding context, with full-note inclusion opt-in.

16. **Major — Stripping frontmatter breaks anchoring unless it produces a source map.** If the model sees transformed content, its quote offsets and surrounding context no longer align with the CM6 document. Introduce a `PreparedDocument` containing transmitted text plus a reversible mapping to the source snapshot. Apply exclusions before reading linked context and fail closed when metadata is unavailable.

17. **Major — Panel output has no usable schema.** The advertised member verdicts, top-three fixes, dissent, aggregate recommendation, and merged findings do not exist in the result contract. Define a typed `PanelResult`, aggregation failure policy, member attribution, conflict/deduplication rules, and behavior when only some members finish. Aggregated edits must retain their original anchors and provenance.

18. **Major — Cost controls are inadequate.** A panel multiplies the entire note and linked context by N, then sends all outputs through another call. A word-count warning and output-token limit do not bound input cost, CLI cost, retry cost, or latency. Add a preflight estimate for the complete context graph, per-run and per-panel budgets, provider-aware concurrency/rate limiting, maximum findings, aggregation caps, and explicit confirmation above cost/context thresholds.

19. **Major — The proposed rail and margin DOM are fragile.** A CM6 gutter is line-oriented and scrolls with content; a persistent persona rail is not naturally a gutter. Appending arbitrary DOM around Obsidian’s editor structure will break across themes, popouts, and layout changes. Prototype a view-owned CM6 panel/plugin element for the rail and prefer an `ItemView` for comments. All DOM must use the view’s document/popout context and registered cleanup.

20. **Major — Inline replacement widgets are a poor default diff mechanism.** Replacing source text with a widget interferes with selection, cursor navigation, Markdown widgets, IME, and overlapping findings. Keep the source visible and show a non-destructive diff tooltip/block widget first. Allow one active proposal per overlapping range, integrate Accept into CM6 undo history, and reject if the source precondition changed.

21. **Major — Floating-card behavior is not specified enough to be implementable.** Missing cases include overlapping findings, viewport clipping, scrolling, soft wrapping, zoom, keyboard focus, Escape, click-away, popouts, and cards whose anchor is virtualized. Use a single active CM6 tooltip per view, collision-aware positioning, and a reliable side-panel fallback. Measure each editor container with a registered `ResizeObserver`; a fixed 900px window threshold is insufficient.

22. **Major — Keyboard triage needs an explicit state machine.** Define active view, active run, sort order, overlapping findings, unanchored/stale findings, focus restoration, behavior inside text inputs, disabled commands, and Escape semantics. Register Obsidian commands with availability checks; do not install broad DOM key handlers. Add ARIA labels, non-color persona indicators, contrast checks, and reduced-motion behavior.

23. **Major — Multiple leaves and popout windows are ignored.** The same file can be open in several CM6 views, each with different viewport and focus state. Decide whether runs belong to a file, a view, or both; keep a file-level controller with per-view projections. The side panel must not blindly equate “active file” with the correct editor instance.

24. **Major — Settings entities lack referential integrity and migrations.** Deleting/disabling an editor can orphan panels and action bindings; deleting a backend can orphan editors and panel aggregation. Import can collide IDs or reference missing entities. Add schema versions, stable UUIDs, migration code, deletion impact dialogs, import validation/remapping, fallback rules, and idempotent starter-pack seeding.

25. **Major — Wikilink autocomplete cannot simply be added to every textarea.** Obsidian’s `AbstractInputSuggest` supports an input or contenteditable div, not `HTMLTextAreaElement`; `EditorSuggest` applies to the note editor. See [AbstractInputSuggest](/home/dsebastien/wks/obsidian-ai-editor/node_modules/obsidian/obsidian.d.ts:294). Use a separate ordered note-reference control with `AbstractInputSuggest`/`FuzzySuggestModal`, or design a tested contenteditable prompt editor. Do not hand-roll a separate autocomplete implementation for every field.

26. **Major — Credential and disclosure requirements are missing.** API keys stored in plugin `data.json` may be synced and are not secure storage. Document this clearly, redact keys/prompts from logs and errors, separate per-device secrets if feasible, and warn on non-loopback HTTP endpoints. Explicit user action is not the same as informed consent to transmit note contents and linked notes.

27. **Major — The fact-checker has no evidence contract.** A critique without sources is another unsupported model claim. Add structured evidence entries with URL/title/claim mapping and distinguish “requires verification” from “verified.” Treat all model output as untrusted text; avoid rendering arbitrary Markdown embeds, HTML, or unsafe links.

28. **Major — Onboarding detection can itself be unsafe or costly.** GUI-launched Obsidian often has a different PATH from the user’s shell. Running `codex --version` may invoke a wrapper that downloads software; a connection test may spend money or transmit sample content. Prefer explicit executable selection, bounded version probes after consent, no installation/update behavior, and a clearly disclosed test payload and expected cost.

29. **Major — Milestone ordering is wrong.** Specific dependency inversions:

   - M1 needs editor/backend configuration that does not arrive until M2.
   - M1’s narrow-layout fallback needs the side panel, but the side panel effectively arrives with M4.
   - M3 exposes panel bindings before panels exist in M4.
   - M3 exposes research actions before CLI capability arrives in M5.
   - M1 depends on unproven structured streaming.
   - Security/privacy, accessibility, manual dual-mode testing, and documentation are deferred to “polish.”

   A safer order is: M0 contracts/threat model plus CM6, transport, and CLI spikes; M1 minimal provider/settings vertical slice; M2 buffered single-editor review with side panel/highlights; M3 streaming/cancellation and mapped anchors; M4 diffs/cards/keyboard; M5 editor/action/context CRUD; M6 panels; M7 opt-in CLI; M8 durable comments.

30. **Major — The testing plan is far too shallow.** Add property/fuzz tests for normalization and duplicate quotes, CM6 transaction-mapping tests, stale-apply tests, provider contract fixtures, adversarial SSE chunking, cancellation races, sidecar migration/corruption tests, and import validation. Each editor milestone needs manual Obsidian verification in Source mode, Live Preview, split panes, popouts, light/dark themes, and narrow layouts; a passing build cannot verify these UI claims.

The plan needs explicit checks for `activeDocument`, `window` timers, registered listeners/observers, themed `Modal` confirmation, safe networking, external-service disclosures, output sanitization, no console logging, CSS lint rules, secret handling, and the extraordinary risk of spawning external executables.
