# Domain Model

Entities and their relationships. Authoritative shapes live in code: `src/app/domain/` (Zod schemas) and `src/app/types/`. This document explains intent.

## Configuration entities (persisted in settings, stable UUIDs)

- **Editor** — an AI persona: name, color, prompt source (text and/or ordered vault note refs), backend instance + model override (or inherit), context policy (opt-in linked notes, cap), capability toggles (review / rewrite / research), optional learning memory (off | settings | vault note), enabled flag.
    - **Learning memory is a full loop** (issue #4, 2026-08-07): the read half injects `memoryText` (settings mode) or attaches the memory note (`prompt-ref`, never link-followed) into the system prompt; the write half is the `Distill editor learnings` command, which consumes the session's **MemoryJournal**, runs one `distill-memory` operation on the editor's own backend, and saves the WHOLE rewritten memory — only through the editable confirmation modal (Business Rules #2/#22). Replacement-not-append is the rotation/cap mechanism. Both modes are editable in the editor dialog (settings mode has its own textarea).
- **Panel** — 1-n member editors + charter (text and/or note refs) + aggregation backend/model. Produces scorecards. Visually distinct from editors everywhere.
- **BackendInstance** — one configured provider (Anthropic / OpenAI / OpenAI-compatible / Azure OpenAI / Ollama) or CLI agent (Claude Code / Codex), with label, credentials/endpoint, default model, negotiated capabilities.
- **ActionBinding** — maps a built-in or custom action verb (rephrase, summarize, critique, say-more, find-evidence, identify-assumptions, simplify, humanize, continue, custom…) to an editor or panel. A custom action additionally carries its name, its instruction prompt source, and its **verb class** (`transform` | `generate` | `review`) — required, never defaulted, because the class decides whether the result replaces the selection, is inserted after it, or comes back as findings.
- **ActionVerb** — what a dispatch path actually runs: label + verb class + instruction. Built-ins come from the verb registry; a custom action supplies its own with the instruction resolved fresh from the vault. `resolveActionVerb` is the only way either becomes one, so nothing downstream can treat them differently (built-ins win over a supplied custom verb: a persisted binding must not redefine what "Humanize" does).
- **BindingRule** — ordered rules matching folder / tag / frontmatter property / note type → **assign** a default reviewer (an editor, or a panel meaning every member) or **disabled** (kill switch: no rail, no menu items, no commands, no dispatch for that scope). Rules only pick participants; they never start anything (Business Rule #1). Resolution order: a matching kill switch wins from any list position, then the first matching assignment in list order (never a union); no match → every enabled review-capable editor. A note's type identity is a SET of identifiers — the Obsidian Starter Kit plugin's own type names when it is installed (optional, feature-detected) plus the `type/<x>` tag convention, which needs no plugin — and a rule matches any of them.
- **VoiceProfile** — global: text and/or note refs; injected into every editor run unless the editor opts out.

## Runtime entities (ephemeral, per session)

- **AssembledContext** — one editor's resolved context for one note: the system prompt (voice + persona + memory text), the vault notes attached with WHY each is there (`prompt-ref` / `wikilink-ref` / `followed-link` / `linked-note` — also the budget's priority order), one **ContextSection** per accounted part (source size, sent size, `sent` | `truncated` | `dropped`) including the ones the budget dropped, and a **ContextBudgetReport** (budget, total sent, overflow, truncated and dropped paths). Built only by `buildEditorPrompt`, which every dispatch path and the "what will be sent" preview go through; the system prompt and the reviewed note are never truncated (a half persona is a different editor, and a trimmed note would make verbatim quoting and anchoring lie — Business Rules #3/#4).
- **DocumentSnapshot** — text + content hash + id, pinned per run. All quotes/anchors are relative to a snapshot.
- **ReviewRun** — one user-triggered execution: target (note/selection), requested editors/panel, per-editor status, findings, panel result. All events carry the run id; late events from cancelled runs are discarded. A run outlives its first pass: one editor can be RETRIED (its findings are replaced) or CONTINUED (its findings are kept and appended) inside the same run, and a panel run additionally owns its aggregation step — see `Architecture.md` § Run lifecycle beyond the first pass for what each does to state.
- **Finding** — one observation by one editor: verbatim quote, critique, a PROPOSAL of 0-10 structured edits (contract v2: op = replace / insert-before / insert-after / delete, each optionally self-anchored by its own quote+hints, defaulting to the finding's span; the edit `text` is applied mechanically and the critique is never written into the note), rationale, severity, confidence, evidence entries (sources), anchor state (anchored / unanchored / stale / ambiguous), status (open / preview / accepted / rejected / dismissed / superseded / error), per-finding thread. Accepting applies ALL edits or none, as one undoable transaction; `invalidProposal` marks a proposal the salvage pass removed (display-only).
- **Finding thread** — session-scoped push-back conversation on ONE finding: `thread` holds COMPLETED exchanges only (strictly alternating user/editor, capped at 6), while the in-flight or failed turn is held separately so no half exchange ever enters the history. The editor's answer either withdraws the finding (`conceded` → dismissed) or holds it, updating critique and/or proposal IN PLACE (`revisedEdits` replaces the edits wholesale, re-anchored against the live text at landing; no live text → the revision degrades to display-only, never fuzzy-relocated).
- **PanelResult** — member verdicts (publish / needs-work / kill) with attribution, aggregated recommendation, top fixes, dissent, partial-failure notes.
- **MemoryJournal** (issue #4) — session-scoped, in-RAM-only record of the user's triage decisions, per editor: `{notePath, quote, critique, severity, decision: accepted|rejected|dismissed|conceded|held, thread}`, clipped at the door (quote ≤300, critique ≤500, thread messages ≤300), FIFO ring capped at 200 per editor, each event stamped with a strictly increasing `seq` (clearing is identity-based: `clear(editorId, upToSeq)` removes only what a distillation snapshotted). `held` is a landed push-back turn the editor defended — non-terminal (a later accept/reject on the same finding is a second event), recorded so push-back-only sessions still distill. Event `notePath`s follow vault renames (`filesRenamedUnder`) so consume-time exclusion checks see current paths. Fed by the `FindingStore`'s `onDecided` choke-point callback, forwarded through the optional `RunObserver.findingDecided` event (the history recorder does not consume it — history archives what editors SAID, the journal captures what the user DECIDED). Never persisted (events quote note content, BR #22); cleared per editor only when a distilled memory is saved. Deliberately NOT fed by carryover registration (already decided), supersede (mechanical), removeMany (retry bookkeeping), or a concession landing on an already-accepted finding.

## Persisted runtime entities (sidecar repository)

- **MarginComment** — a question the user parked on a span, answered in the background, that OUTLIVES the session. Note path (the store's key) + the locating hints `quote`/`prefix`/`suffix`/`occurrence` and **no offsets** — a stored position would look authoritative after an edit made while Obsidian was closed — plus the user instruction, the executing editor (id + the name as it was, so a deleted editor still reads sensibly), status (submitted / running / interrupted / done / dismissed), timestamps, and the result (findings, optional reply, redacted error).
    - Re-anchored on load against the live text through the same `matchQuote` engine findings use: **exact** (verbatim, unique or hint-disambiguated), **fuzzy** (normalized match — anchored, and its `anchoredText` is sliced from the source so preconditions still compare real text), **orphaned** (not found or ambiguous: kept and shown with its quote, never guessed into a position, never deleted).
    - `submitted`/`running` describe the current session only; read back from disk they mean the session died mid-job, so they load as **interrupted** — which offers Retry and never resumes anything (a resumed request would be a backend call this session never authorized, Business Rule #1).

## Key relationships

```
BindingRule ──selects──▶ Editor(s) | Panel | disabled
Panel ──members──▶ Editor (1-n)
ActionBinding ──routes──▶ Editor | Panel
Editor ──runs-on──▶ BackendInstance (or inherits global default)
ReviewRun ──pins──▶ DocumentSnapshot ──anchors──▶ Finding
Finding ──thread──▶ ThreadTurn* ──may-produce──▶ revised edits
Panel run ──aggregates──▶ member ReviewRun results ──▶ PanelResult
```
