# 2026-07-31

## The plugin identity becomes `editor-ai-daemons` / "Editor AI Daemons"

The v1 blocker recorded on 2026-07-30 (`documentation/community-review-checklist.md` § 0) is closed. Three commits: `2e3e226` (manifest/package/CSS prefix/display name), `d8d778a` (CLI prefix, view type, menu section, export marker, frontmatter key), + this docs commit. Specs unchanged at **2 258** — the rename is mechanical, and every existing spec that pins an identity string moved with it.

### The decision

`id: ai-editor` and `name: "AI Editor"` are both already published in the community catalog by another author (`buszk/obsidian-ai-editor`). A duplicate id is refused outright, the catalog pins the slug from the FIRST submission, and the id is unchangeable once accepted — so this had to be settled before submitting, and `manifest.json` still saying `0.0.0` made 2026-07-31 the cheapest possible moment.

Sébastien picked **`editor-ai-daemons` / "Editor AI Daemons"** after checking two things: the pair is free in the catalog, and no recent plugin uses an `obsidian-` id prefix, so dropping the prefix costs nothing in discoverability. "Daemons" is also the vocabulary the plugin already uses for its own behaviour — an editor in daemon mode watches the file and refreshes its own recommendations.

Availability re-verified the same day against the live `community-plugins.json` (6 210 entries): the id is free, the name is free case-insensitively, and **no catalog entry has "daemon" anywhere in its `id` or `name`** — the collision surface is empty, not merely clear on an exact match. The old `ai-editor` entry is still there, still `buszk`. The exact commands are in checklist § 0.

### The repository name did NOT change

This is the constraint that shaped every replacement. The GitHub repo stays `dsebastien/obsidian-ai-editor`, the local folder stays `~/wks/obsidian-ai-editor`, and the catalog only ever gated the manifest `id` — the repo name is allowed to keep "obsidian" in it. So a blind `sed` over the tree would have corrupted things that must not move:

- Every repo URL: README download/BRAT/issue links, `docs/README.md`, `docs/install.md`, `docs/troubleshooting.md`, `package.json` `repository`/`bugs`/`homepage`, `docs/_config.yml` `baseurl: /obsidian-ai-editor` and its GitHub link, `https://dsebastien.github.io/obsidian-ai-editor/`.
- The OpenRouter attribution header `http-referer` (`src/app/services/backends/providers/openai.ts`), which points at the repo.
- The CLI sandbox temp-dir prefix `obsidian-ai-editor-` (`src/app/services/backends/cli/node-fs.ts`), derived from the repo name.
- `src/app/ui/support-links.spec.ts`, which asserts the support table does NOT leak a repo URL.

Every replacement therefore ran with a `(?<!obsidian-)` guard or an explicit file list, and the leftover set was inspected by hand after each pass: what remains matching `ai-editor` in shipped code is exactly the list above.

### Three decisions worth recording

**The CSS prefix follows the id because the build already says so.** `scripts/build.spec.ts` pins the What's New view's classes to `manifest.id` (`${id}-whats-new-*`, built at runtime in `src/app/ui/whats-new-view.ts` from `entry.pluginId`). That spec went red the moment the manifest changed and green again the moment the stylesheet followed — the convention is enforced, not folklore. Every other `editor-ai-daemons-*` class was renamed to match.

**The CLI prefix follows the id because `registerCliHandler` says so.** Obsidian's contract is `<plugin-id>` / `<plugin-id>:<action>`; `REVIEW_CLI_COMMAND`, `CANCEL_CLI_COMMAND` and `STATUS_CLI_COMMAND` are the only three literals and they all moved together, so `cli-shared.ts`'s lockstep guarantee (a finding printed by `:status` has the same shape as one printed by `:review`) is unaffected.

**Command ids needed nothing.** All 16 `addCommand` ids (`review-current-note`, `cancel-run`, `setup-wizard`, …) plus the dynamic action/bulk commands are bare verbs — Obsidian namespaces them with the plugin id at registration, so none of them embedded `ai-editor` and none was touched. User hotkeys are moot anyway (nothing has shipped), but the ids are also the stable API and there was no reason to churn them.

### Dated history was left alone on purpose

`documentation/history/2026-07-29.md`, `documentation/history/2026-07-30.md` and `documentation/reviews/2026-07-29-plan-review-codex-gpt-5.6-sol.md` still say `ai-editor` throughout. That is correct: they are a dated record of what the plugin was and what commits introduced, and 2026-07-30 in particular records the catalog collision itself — rewriting `ai-editor` there would turn "the id `ai-editor` is already published by buszk" into a false statement. Living documents (README, `docs/**`, `Architecture.md`, `Configuration.md`, the interaction-surfaces design, the v1 plan's spec sections) were updated; the milestone rows in the plan's § 0 status table, being a dated narrative, were not, apart from the v1 row's blocker item and the new rename row.

`documentation/plans/ai-editor-v1-implementation-plan.md` keeps its filename. It is an internal document path, not plugin identity, and renaming it would break every cross-reference in the history files for no gain.

### Verification

The stylesheet was the one place a mechanical rename could silently drop rules, so it was measured before and after:

```bash
grep -oF '{' dist/styles.css | wc -l                                   # 327 → 327
grep -oF 'ai-editor' dist/styles.css | wc -l                           # 375 → 0
grep -oE '(^|[}])\.[a-zA-Z0-9_-]+' dist/styles.css | sed 's/^}//' | sort -u | wc -l   # 219 → 219
```

and the two selector sets are byte-identical once the prefix is normalised (`sed 's/^\.editor-ai-daemons-/.ai-editor-/'` then `diff`). Same rule count, same selector count, same selectors, zero occurrences of the old name.

Gates green after each chunk: `bun run format`, `bun run validate` (tsc + eslint `--max-warnings 0` + 2 258 specs), `bun run build`.

### Still open

Unchanged by this work, and still Sébastien's: pushing (everything is local), the marketplace submission itself, docs-site publishing/screenshots/video, and the live-vault verification list at the end of `documentation/history/2026-07-30.md`.

**Three test-vault migrations are new.** All three are pre-release chores — nothing has shipped, `manifest.json` is still `0.0.0` — but they need doing before the next live run:

1. **Plugin folder.** It is now `.obsidian/plugins/editor-ai-daemons/`; an existing `ai-editor` folder there is stale and its `data.json` will not be picked up. Move it, or re-run the setup wizard. Fails loudly: settings simply do not load.
2. **Frontmatter opt-out key.** `ai_editor: false` no longer excludes a note — `src/app/services/context/exclusions.ts` reads only `metadata.frontmatter['editor_ai_daemons']`, with no fallback. Rekey any such note to `editor_ai_daemons: false` **first**. This is the one migration that fails _silently, in the privacy direction_: a note that was previously never sent anywhere gets sent to a backend on the next run, with no notice, no skip report and no log line.
3. **Settings exports.** The marker moved (`src/app/domain/settings/settings-transfer.ts`, `EXPORT_FORMAT = 'editor-ai-daemons-settings'`; default path `editor-ai-daemons-settings.json`), so any `ai-editor-settings.json` produced during the 2026-07-30 live-verification pass is now rejected on import with "That JSON is not an Editor AI Daemons export." Re-export after the rename.

One judgement call to confirm: the OpenRouter `x-title` attribution header now reads `Editor AI Daemons (Obsidian)` (it is the plugin's display name, shown in OpenRouter's app rankings). Its sibling `http-referer` still points at `github.com/dsebastien/obsidian-ai-editor`, as required.
